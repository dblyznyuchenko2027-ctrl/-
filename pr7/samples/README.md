# Зразки документів

Рахунки на оплату, які постачальники надсилають магазину «Сузірʼя». Усі документи, компанії, коди й рахунки **вигадані**; коди ЄДРПОУ, РНОКПП і IBAN побудовано за справжніми правилами, тож перевірки контрольних сум на них працюють.

## Що тут є

| Папка | Що всередині |
|---|---|
| `clean/` | 9 документів гарної якості, PNG 1240 × 1754 (A4 при 150 dpi) |
| `degraded/` | ті самі `rahunok-01`, `rahunok-03`, `rahunok-05`, кожен у шести погіршених варіантах, JPEG |
| `own/` | ваші власні зразки; папки немає, доки ви її не створите, до репозиторію вона не потрапляє |
| `expected.json` | правильні значення полів для кожного файлу і те, що мало б статися з документом |

## Документи

| Файл | Що в ньому особливого |
|---|---|
| `rahunok-01` | звичайний рахунок платника ПДВ, три позиції; дата словами |
| `rahunok-02` | ФОП, неплатник ПДВ: код — РНОКПП із 10 цифр, ПДВ немає |
| `rahunok-03` | одинадцять позицій, дрібніший шрифт, дробові ціни |
| `rahunok-04` | строку дії в документі немає |
| `rahunok-05` | помилка постачальника: 3 × 4 250,00 надруковано як 12 570,00 |
| `rahunok-06` | у надрукованому IBAN переставлено дві цифри |
| `rahunok-07` | рахунок виставлено іншому покупцеві |
| `rahunok-08` | «змінено банківські реквізити» і дрібний текст, адресований системі обробки |
| `nakladna-09` | не рахунок, а видаткова накладна |

## Погіршені варіанти

| Суфікс | Що зроблено |
|---|---|
| `-blur` | розмиття: нечіткий скан, рух камери |
| `-lowres` | роздільність зменшено приблизно до третини |
| `-jpeg` | сильне стиснення JPEG |
| `-faded` | вицвілий друк: низький контраст |
| `-photo` | фото телефоном: перспектива, нахил, тінь, шум |
| `-crop` | низ документа обрізано: підсумків і строку дії на знімку немає |

Власні варіанти робить `degrade.py` у корені роботи.

## Формат `expected.json`

Ключ — шлях до файлу відносно `samples/`. Для кожного файлу:

- `fields` — правильні значення. Дати — `РРРР-ММ-ДД`, суми — рядки з двома знаками після крапки (`"12570.00"`), щоб не губити копійки в числах із рухомою комою; IBAN — без пробілів; назви — як надруковано. Значення, якого в документі немає або якого не видно на знімку, — `null`.
- `expected_checks` — які правила **мали б** спрацювати: `arithmetic_line`, `iban_checksum`, `iban_registry`, `buyer`, `document_type`, `missing_required`. Назви умовні — ваші правила можуть називатися інакше.
- `expected_decision` — `auto`, `review` або `reject`.
- `note` — що в документі особливого.

Імена полів у `fields` — не вимога до вашої схеми. Порівнюючи, зіставте свої поля з цими.

Значення в `fields` — те, що **надруковано**, а не те, що мало б бути. У `rahunok-05` сума другого рядка — `12570.00`: модель, яка «виправила» її на `12750.00`, помилилася, навіть якщо арифметично має рацію.
