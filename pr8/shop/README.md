# Внутрішній сервіс магазину «Сузірʼя»

Готовий модуль, який у цій роботі грає роль бекенду: замовлення, каталог, склад, доставка, повернення. **Змінювати його не потрібно** — ви підключаєте його функції до мовної моделі як інструменти в `app/tools.py`.

Сервіс внутрішній: ним користуються оператори, склад і бухгалтерія. Тому він **не знає, хто звертається**, і не перевіряє, чиє замовлення читають чи змінюють; повертає записи **цілком**, зі службовими полями; і має операції, яких клієнт не може виконати ні в кабінеті, ні через оператора. Усе, що з цього випливає для помічника клієнта, — ваше рішення.

## Функції

| Функція | Що робить | Звідки дані |
|---|---|---|
| `get_customer(customer_id)` | профіль: імʼя, email, телефон, адреса, бонуси | `customers.json` |
| `list_orders(customer_id)` | замовлення клієнта: номер, дата, статус, сума, кількість товарів | `orders.json` |
| `get_order(order_id)` | замовлення цілком: власник, позиції, доставка з номером відправлення, оплата, **службова примітка оператора** | `orders.json` |
| `search_products(query, category, max_price, limit)` | пошук у каталозі: усі слова запиту мають трапитися в назві, категорії чи описі | `products.json` |
| `get_product(sku)` | картка товару: ціна, вага, гарантія, чи повертається товар належної якості, опис | `products.json` |
| `get_stock(sku)` | скільки доступно на складі; коли очікується поставка | `stock.json` |
| `delivery_quote(city, method, items)` | вартість і строк доставки набору `[{"sku", "quantity"}]`; `method` — `branch`, `courier`, `pickup` | `tariffs.json` |
| `create_return(order_id, sku, reason, quantity, comment)` | заявка на повернення; `reason` — `not_suitable`, `defect`, `wrong_item`, `damaged` | у памʼяті |
| `list_returns(order_id)` | створені заявки на повернення | у памʼяті |
| `cancel_order(order_id)` | скасувати замовлення в статусі «Готується» | у памʼяті |

**Адміністративні операції** — для бухгалтерії й керівника підтримки:

| Функція | Що робить |
|---|---|
| `set_order_status(order_id, status)` | примусово змінити статус |
| `issue_refund(order_id, amount)` | повернути кошти на картку |
| `update_price(sku, price)` | змінити ціну в каталозі |
| `add_bonus(customer_id, amount)` | нарахувати бонуси |

Службові: `list_customers()` — ідентифікатор, імʼя й місто кожного клієнта (для сторінки, яка імітує вхід), `reset()` — повернути дані до початкового стану, `today()` — сьогоднішня дата сервісу.

## Правила, які сервіс перевіряє сам

- Повернення — лише для отриманого замовлення і лише товару, який у ньому є.
- Товар належної якості (`not_suitable`) — протягом 14 днів з отримання і лише якщо `returnable` у картці товару; навушники-вкладиші й витратні матеріали не повертаються.
- Дефект (`defect`) — протягом гарантійного строку.
- Скасування — лише в статусі «Готується».
- Доставка — лише по Україні, у міста з переліку перевізника; безкоштовно у відділення від 2000 грн, крім великогабаритних товарів.

Чого сервіс **не** перевіряє: чиє це замовлення, чи клієнт справді хоче саме цього, чи така сама заявка вже існує.

## Помилки

Усі помилки — підкласи `ShopError`, у кожного є поле `code`:

| Клас | `code` | Коли |
|---|---|---|
| `NotFound` | `not_found` | немає замовлення, товару, клієнта |
| `InvalidRequest` | `invalid_request` | некоректні параметри: невідомий спосіб доставки, місто, причина, кількість |
| `PolicyViolation` | `policy` | запит зрозумілий, але правила магазину його не дозволяють |
| `Unavailable` | `unavailable` | сервіс не відповів |

Текст помилки — для людини, українською.

## Дата, затримки, відмови

Сьогоднішня дата сервісу зафіксована — `2026-10-06`, щоб строки повернення в даних не «старіли». Змінити — `SHOP_TODAY` у `.env`.

Щоб перевірити, як застосунок переживає повільний або ненадійний сервіс, задайте в `.env`:

```
SHOP_DELAY_MS=1500
SHOP_FAILURE_RATE=0.3
```

Перше додає затримку до кожного виклику, друге — частку викликів, що завершаються `Unavailable`.

## Дані

Усі клієнти, замовлення й товари вигадані. Зміни (повернення, скасування, ціни) живуть лише в памʼяті процесу: перезапуск застосунку або `reset()` повертає початковий стан.
