# Колекція документів — інтернет-магазин «Сузірʼя»

Це та сама база знань магазину, що й у ПР5, — без змін, щоб ваш індекс
і поділ на фрагменти працювали як є. Колекція починалася з ПР3 і ПР4. Тоді всі правила
вміщувалися в один `context.md` і йшли в кожен запит до моделі цілком. Тут
їх стало більше: правила розписано докладніше, додалися інструкції до
товарів, відповіді на часті запитання, програма лояльності, довідник
сервісних центрів і внутрішня інструкція для операторів.

Файли є **даними застосунку**: код їх читає, ділить на фрагменти й
індексує. Додавання чи заміна файлу не має вимагати зміни коду — лише
перебудови індексу.

## Метадані

Кожен файл починається з блоку метаданих між рядками `---`:

```
---
title: Доставка
category: правила
product:
audience: клієнти
updated: 2026-08-01
status: чинний
---
```

| Поле | Значення | Навіщо |
|---|---|---|
| `title` | назва документа | показати в результатах |
| `category` | `правила`, `гарантія`, `faq`, `інструкція`, `програма`, `політика`, `довідник`, `внутрішнє` | фільтр за видом документа |
| `product` | назва товару або порожньо | фільтр за товаром для інструкцій |
| `audience` | `клієнти` або `персонал` | те, що призначене персоналу, клієнт бачити не має |
| `updated` | дата останньої редакції | відрізнити чинну версію від застарілої |
| `status` | `чинний` або `архів` | архівні документи лишено навмисно: у справжній базі знань вони теж є |

Решта файлу — звичайний Markdown із заголовками другого рівня. Заголовки —
природні межі фрагментів, але чи користуватися ними — ваше рішення.

наперед.

Тексти вигадані для навчальних цілей. Збіги назв товарів і організацій з
реальними випадкові.
